# СтейджРент CRM — синхронізація між пристроями (Supabase)

Ця версія зберігає дані у спільній хмарній базі даних, тож ноутбук,
телефон і будь-який інший пристрій бачитимуть **одні й ті самі дані**,
і зміни з'являються на інших пристроях практично миттєво — без
перезавантаження сторінки.

Дані, які ви вже встигли ввести на ноутбуці, **не загубляться** —
нижче є крок, який автоматично перенесе їх у нову базу при першому
відкритті оновленого сайту саме на тому ноутбуці.

## Крок 1. Створіть базу даних на Supabase

1. Зайдіть на https://supabase.com → "Start your project" → зареєструйтесь
   (можна через GitHub).
2. Натисніть "New project". Виберіть будь-яку назву й пароль до бази
   (пароль просто збережіть собі, далі не знадобиться) і регіон
   (найближчий, наприклад Frankfurt). Створення триває 1-2 хвилини.
3. Коли проєкт створено, зайдіть у розділ **SQL Editor** (іконка з
   лівого боку) → "New query".
4. Відкрийте файл `supabase-setup.sql` з цього проєкту, скопіюйте
   весь його вміст, вставте в редактор і натисніть **Run**. Це
   створить таблицю для зберігання даних.
5. Перейдіть у **Project Settings → API**. Там будуть два значення,
   які знадобляться далі:
   - **Project URL** (виглядає як `https://xxxxxxxx.supabase.co`)
   - **anon public** ключ (довгий рядок символів)

## Крок 2. Оновіть файли в GitHub

У вашому репозиторії на GitHub потрібно **замінити/додати** такі файли
(вміст кожного — з цього оновленого проєкту):

| Файл | Дія |
|---|---|
| `src/supabaseClient.js` | новий файл — створити |
| `src/storage-supabase.js` | новий файл — створити |
| `src/main.jsx` | замінити вміст (тепер підключає `storage-supabase.js`) |
| `src/App.jsx` | замінити вміст (додано автоперенесення старих даних і живу синхронізацію) |
| `package.json` | замінити вміст (додано залежність `@supabase/supabase-js`) |

Для кожного файлу: відкрийте його на GitHub → значок олівця
(Edit) → виділіть все, видаліть → вставте новий вміст → **Commit
changes**. Для нових файлів — "Add file → Create new file", ввести
шлях (наприклад `src/supabaseClient.js`), вставити вміст, Commit.

## Крок 3. Додайте ключі Supabase у Vercel

1. Відкрийте ваш проєкт на https://vercel.com → **Settings →
   Environment Variables**.
2. Додайте дві змінні:
   - `VITE_SUPABASE_URL` → значення Project URL з кроку 1
   - `VITE_SUPABASE_ANON_KEY` → значення anon public ключа з кроку 1
3. Збережіть.

## Крок 4. Перезапустіть деплой

Vercel → вкладка **Deployments** → три крапки біля останнього деплою
→ **Redeploy**. Через 1-2 хвилини сайт оновиться.

## Крок 5. Перенесення вже введених даних

Відкрийте оновлений сайт **саме на тому ноутбуці**, де ви вносили
дані раніше. При відкритті застосунок сам виявить, що в базі ще
порожньо, знайде дані, що лежали в цьому браузері, і одразу перенесе
їх у спільну базу — більше нічого робити не треба. Після цього
відкрийте сайт на телефоні — там вже мають бути ті самі дані.

Якщо на телефоні раніше теж встигли щось окремо додати (чого немає
на ноутбуці) — ці записи перенесені не будуть автоматично, їх
доведеться внести вручну ще раз (перенесення працює лише один раз, з
першого пристрою, який відкриє оновлену версію).

## Далі

Синхронізація готова — можна користуватись з будь-якої кількості
пристроїв одночасно. Якщо згодом захочете, щоб у кожного співробітника
був окремий логін і права доступу — це наступний окремий крок,
скажіть, коли буде актуально.
